# Read-only Git smart HTTP through CGI

This reverse-bin command-app example serves Git smart HTTP using Caddy's CGI module and Git's stock `git-http-backend`.

## Security model

- Caddy listens only on `data/reverse-bin.sock`; no TCP bind permission is needed.
- Put Caddy in `bin/caddy` and Git repositories outside `data/`. Reverse-bin exposes the app tree read-only and grants writes only to `data/`.
- The Caddy routes reject receive-pack requests, and each bare repository sets `http.receivepack=false`.
- `GIT_HTTP_EXPORT_ALL` is intentionally absent. Export repositories individually with an empty `git-daemon-export-ok` marker.
- The CGI executable is outside any file-server document root.
- Build versions and the Docker builder digest are pinned.

## Setup

Copy this directory into the reverse-bin app root, then:

```bash
mv reverse-bin.env.example .env
mkdir -p bin data repo/team
./build-caddy.sh
git init --bare --initial-branch=main repo/team/project.git
git -C repo/team/project.git config http.receivepack false
touch repo/team/project.git/git-daemon-export-ok
```

Set `GIT_PROJECT_ROOT` in `.env` to the canonical absolute `repo/` path. Publish from the host; do not grant the sandbox write access to `repo/` or `bin/`.

Clone through the app hostname:

```bash
git clone https://APP.EXAMPLE/team/project.git
```

Verify the sandbox generated by the detector has only the app's `data/` directory as writable and does not contain `--bind-tcp`.
